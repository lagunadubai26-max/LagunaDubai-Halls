# بيانات القاعات — جاهزة لـ opencode

ده تلخيص وتنظيم لكل الملفات اللي رفعتها (2 صور بروشورات، 2 عقد قاعة روز المتطابقين، وإيصال/عقد قاعة لوشاتو) في ملف واحد structured: **`halls-data.json`**.

## الملفات
- **`halls-data.json`** → البيانات نفسها (3 قاعات: كريستالة، روز، لوشاتو) بصيغة JSON منظمة، جاهزة تتحط في seed data أو تتحول لجداول DB مباشرة.
- **هذا الملف** → شرح للموديل المقترح + أي حاجة ناقصة محتاجة تأكيد منك قبل ما opencode يبني عليها.

## موديل البيانات المقترح (للنظام ككل)
الثلاث قاعات مختلفين في طريقة التسعير، فالـ schema لازم يستحمّل الفروق دي:

| Table | ملاحظات |
|---|---|
| `halls` | id, name, address, city, phones, capacity (nullable — لوشاتو مفيهاش سعة ثابتة) |
| `packages` | hall_id, tier_name, price (nullable), currency — عند كريستالة فيه باقة أساسية واحدة بس، عند روز 4 باقات متدرجة، عند لوشاتو مفيش باقات خالص (تسعير يدوي لكل حجز) |
| `package_includes` | package_id, item_name — قايمة الخدمات جوه كل باقة |
| `addons` | hall_id, name, price (كلها `null` حالياً — مفيش أسعار مطبوعة للإضافات في أي مصدر) |
| `contracts` | hall_id, client_name, client_national_id, client_phone, event_type, event_date, guest_count, total_amount, deposit_amount, deposit_receipt_no, remaining_amount, remaining_due_date, security_deposit_amount |
| `contract_terms` | hall_id, cancellation_policy (JSON/array), date_change_fee_percent, jurisdiction, prohibited_items |

ده اقتراح بس — لو `opencode` هيبني على schema مختلف خالص، الـ JSON already فيه كل الداتا الخام عشان يتقسم زي ما يناسب المشروع.

## أسعار قاعة روز (مؤكدة منك)
عرض أول 25,000 / عرض تاني 27,000 / عرض تالت 29,000 / عرض رابع 31,000 جنيه — الملف اتحدّث بالأرقام دي.

## حاجات لسه محتاجة تأكيد منك (فجوات في البيانات)
1. **قاعة كريستالة**: البروشور مفيهوش أي أسعار خالص — لا للباقة الأساسية ولا للإضافات (التورتة، الفوتوجرافر). لو النظام هيعرض أسعار لازم تجيبها من حتة تانية.
2. **قاعة روز**: مفيش عنوان أو رقم تليفون مطبوع في أي من المصدرين (لا البروشور ولا العقد) — استنتجت إن القاعة في ميت غمر بس من بند الاختصاص القضائي في العقد.
3. **قاعة لوشاتو**: مفيش باقات أو أسعار منشورة خالص — العقد نفسه بيقول إن العميل "اطلع على تعليمات إقامة الأفراح والحفلات وأسعارها" في المكتب، يعني التسعير كله يدوي وقت الحجز. لو عايز تسجّلها في النظام كـ packages محتاج تجيبلي الأسعار الفعلية.
4. **إضافات قاعة روز** (شو فاير، زفة دمياطي، دبكة سوري...إلخ) مذكورة كأسماء بس من غير أسعار.

## Prompt جاهز تدّيه لـ opencode
```
عندي نظام إدارة قاعات أفراح/حفلات، وعندي بيانات 3 قاعات حقيقية في ملف halls-data.json
(باقات، إضافات، شروط تعاقد، حقول العقد لكل قاعة). المطلوب:
1. تصميم schema عام (halls, packages, package_includes, addons, contracts, contract_terms)
   يستحمّل اختلاف نموذج التسعير بين القاعات (باقة واحدة ثابتة / باقات متدرجة / تسعير يدوي بدون باقات).
2. سيد الداتا (seed) من الملف المرفق كبيانات ابتدائية حقيقية.
3. أي price = null لازم يفضل قابل للتعديل من لوحة تحكم صاحب القاعة، مش hardcoded.
```

جهّزت الملفين خلاص — عايزني أزود عليهم حاجة، أو أبني منهم مباشرة صفحة/API تجريبية هنا في المحادثة؟
